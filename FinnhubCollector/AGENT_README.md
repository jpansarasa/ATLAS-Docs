# FinnhubCollector — architecture [agent read-first]

PURPOSE: poll Finnhub REST->persist subset->re-serve via gRPC. Not threshold-eval, not alert, not instrument-registry (registers TO SecMaster, f-a-f). source-of-truth=own collected snapshots, not live-market-state.

DATA MODEL + INVARIANTS:
  INV series-id: DB=`FH-{TYPE}-{SYMBOL}` (dashes) != gRPC SeriesId=`FH/{symbol}` (slash). client filter must use `FH/` prefix.
  INV candle-dual-linkage: Candle has BOTH denormalized series_id STRING col AND nullable series_config_id INT FK->finnhub_series. two separate cols for same linkage; lookup-by-string != join-by-FK. (moot: nothing writes candles.)
  INV no-FK-on-symbol-tables: finnhub_news_sentiment/insider/recs/price_targets/profiles/calendars key on symbol+time — NO FK->finnhub_series. schema does not enforce series exists.
  INV dedup-key-varies: not uniform (symbol,collected_at). quotes=(symbol,timestamp); news_sentiment=(symbol,collected_at); insider=(symbol,year,month); recs=(symbol,period); profiles=(symbol); econ-cal=(country,event,event_time). wrong-key->silent miss.
  INV stamps-single-writer: `finnhub_quote_collection_stamps` (PK symbol, one row rewritten in place) is written by QuoteCollectionWorker ONLY, for symbols it actually collected. It is the staleness ORIGIN, not a data table — a second writer (admin-collect, a backfill, a repair script) silently disarms the dead-man across the next restart. Deliberately NOT max(collected_at) from finnhub_quotes: that table has two writers, and `trigger_collection` is the first diagnostic anyone runs during a stall (D-2).
  INV BullishPercent⊥: Ignore()d derived prop in finnhub_recommendations != mapped bullish_percent COLUMN in finnhub_news_sentiment. same name, different treatment per table.
  LIVE-WRITE PATHS: QuoteCollectionWorker(loop,Quote only; ALSO the sole writer of finnhub_quote_collection_stamps) + admin-collect(trigger,Quote/NewsSentiment/Recommendation/PriceTarget/CompanyProfile; writes finnhub_quotes and last_collected_at, NEVER the stamps). Candle/social/insider/calendars=dead-schema: upsert methods exist, 0 callers -> tables permanently empty -> MCP+/api/* reads return empty.

PATHS (distinct code — do not conflate):
  QuoteCollectionWorker [BackgroundService, 1-min loop, 10s startup]
    does: GetActiveSeriesAsync(Quote)->TrackActiveSymbols(gauge series set)->rate-limit->GetQuoteAsync->UpsertQuoteAsync->MarkQuoteCollected(symbol)->UpdateLastCollectedAt; once per cycle, persists the collected symbols to finnhub_quote_collection_stamps and THEN arms finnhub_quote_staleness_origin_durable for exactly those symbols (D-2).
    does NOT: non-Quote types; SecMaster registration; push anywhere — the upsert IS the publish (ThresholdEngine PULLS from finnhub_quotes over gRPC); stamp a symbol whose quote came back null.
    on-miss(null quote): UpsertQuoteAsync SKIPPED; UpdateLastCollectedAt fires UNCONDITIONALLY outside null-guard -> LastCollectedAt advances on empty response, but the staleness gauge for THAT SYMBOL keeps climbing (deliberate, D-2 (b)).
    on-miss(stamp write fails): caught, WARNING + finnhub_collection_errors_total{operation="persist_quote_stamps"}, cycle continues. Fail-safe: the in-memory gauge is already stamped, the durable origin freezes, and the NEXT restart comes up looking stale — which pages.
  QuoteStalenessSeeder [IHostedService, StartAsync only, registered BEFORE QuoteCollectionWorker]
    does: reads finnhub_quote_collection_stamps ONCE at startup and seeds each symbol's staleness origin, so the gauges survive a restart (D-2 (d)); an ACCEPTED seed arms that symbol's finnhub_quote_staleness_origin_durable. does NOT set any service-wide armed flag — reading the table is not evidence that any origin was restored (D-2 (f)).
    does NOT: collect; write; run after StartAsync; ever LOWER staleness; ever overwrite an origin a cycle already stamped (so start ORDER cannot change the outcome).
    on-miss(empty store): WARNING + finnhub_quote_staleness_origin_durable=0 -> the alert's third leg fires; self-clears on the first cycle that persists a stamp. DB failure: same, non-fatal, startup continues. A cancelled token during boot is rethrown, NOT reported as a blind dead-man.
  admin-collect [HTTP POST /api/admin/series/{id}/collect · ops/MCP]
    does: type-switch->single collect(Quote/NewsSentiment/Recommendation/PriceTarget/CompanyProfile); queued via BackgroundCollectionQueue(DropWrite@100, dup-suppressed).
    does NOT: Candle; calendars; insider; social (all fall to default+warn).
    on-miss: 404(series absent); 429(queue full OR already queued).
  stored-reads [HTTP GET /api/* · ApiEndpoints->IFinnhubRepository]
    does: read latest/history from DB.
    does NOT: Finnhub call; write. /api/market/status, /api/symbols/search, /api/discover = exceptions->proxy live Finnhub.
    on-miss: 404.
  live-passthrough [HTTP GET /api/live/* · LiveDataEndpoints->IFinnhubApiClient]
    does: direct Finnhub call, tags source="finnhub-live". includes /api/live/peers/{symbol}.
    does NOT: read DB; write DB.
  gRPC-stream [ObservationEventStream :5001 · ThresholdEngine]
    does: Subscribe/GetEventsSince/Between/GetLatestEventTime/GetHealth over finnhub_quotes only.
    does NOT: candles; sentiment; calendars (never stored -> never streamed).
    on-miss(empty table): GetLatestEventTime returns DateTime.UtcNow, not null/sentinel -> consumer polling "latest time" sees forever-advancing clock against empty table. Never use as new-data signal naively.
  gRPC port: Program.cs logs the actual bound port from Kestrel:GrpcPort (default 5001). ThresholdEngine subscribes ObservationEventStream on :5001.

PROCESSING MODEL: WaitForTokenAsync(token-bucket 60/min,RATE_LIMITER_CAPACITY) -> Finnhub HTTP(Polly: 3x exp-retry, CB 5-fail/60s, 30s timeout) -> upsert(UNIQUE idempotent) -> UpdateLastCollectedAt.
MAXIM: store-then-serve; DB table=event log; nothing is pushed. finnhub_quotes IS the publish surface — EventRepository reads it directly and gRPC serves it. A collector that "emits an event" here means it wrote a row.
PROFILE2 NEGATIVE-CACHE: GetCompanyProfileAsync remembers symbols that returned a permanent 4xx (403=plan-uncovered foreign listing · 404=unknown) in a static (process-wide) cache and SKIPS re-calling them for ProfileNegativeCacheTtl (default 24h, `Finnhub:ProfileNegativeCacheTtlHours`) — stops per-cycle quota burn + WARN spam on uncovered listings. 429/5xx NOT cached (transient). First 403/404/429 logs Info (not WARN); subsequent skips are Debug-only.

DISTINCTIONS:
  live(/api/live/* + /api/market/status + /api/symbols/search + /api/discover) ≠ stored(/api/quotes,/api/sentiment,/api/analyst,/api/company): live=Finnhub-each-call+no-persist; stored=DB-only.
  /api/symbols/search+/api/discover(upstream Finnhub discovery) ≠ /api/search(UnifiedSearch over LOCAL finnhub_series for SecMaster gateway).
  BackgroundCollectionQueue(admin-collect work queue,HAS reader,DropWrite,depth=finnhub_collection_queue_depth) is the ONLY channel left in this service. It is NOT in the quote path — `finnhub_collection_queue_depth` says nothing about quote collection, and reading it as such is the mistake D-2 exists to prevent. Quote-collection health is `finnhub_quote_collection_staleness_seconds{symbol}`, one series per active Quote series.
  DI(namespace FinnhubCollector,src/DependencyInjection.cs) ≠ DI(namespace FinnhubCollector.Services,src/Services/ApplicationDependencyInjection.cs). same class name, two namespaces.

CROSS-SERVICE:
  OUT(sync): Finnhub API (all data). OUT(f-a-f,optional): SecMaster RegisterSeriesAsync(assetClass=Equity; symbol=ticker; metadata["alias"]=FH/{symbol} stream id -> SecMaster series_id alias so ThresholdEngine pattern symbols resolve; gated SECMASTER_GRPC_ENDPOINT; failures=WARN,non-blocking). Backfill: POST /api/admin/series/register?seriesId=... (awaited, idempotent; query param because legacy FH/{sym} ids contain '/'). OUT: OTLP->otel-collector.
  IN(gRPC :5001): ThresholdEngine subscribes ObservationEventStream.
  FEEDS: ThresholdEngine via quote events; SecMaster catalog+sector via registration+/api/search+/api/discover gateway.

DECISIONS:
  D-2 quote-path-no-in-process-queue: INTENT quote collection reaches ThresholdEngine by being STORED, not by being pushed — UpsertQuoteAsync writes finnhub_quotes, EventRepository reads that table, gRPC ObservationEventStream serves it, TE pulls. So an in-process queue in the cycle carries no data anywhere and can only add a way to stop. One did: Channel.CreateBounded(1000) with FullMode=Wait whose .Reader was referenced NOWHERE in the repo (its intended consumer, IEventPublisher, had zero implementations from the day it was written). Write #1001 parked, the loop halted mid-cycle, and prod collected nothing from 2026-07-31T21:34:45Z to 2026-08-17 — Up, RestartCount 0, zero errors logged, and it recurred on every restart ~56min in. Channel and interface both DELETED; the second half of the intent is that the halt must now be VISIBLE however it happens, which means visible per SYMBOL, across a RESTART, and even when the detector itself has failed. / PRECOND (a) nothing in the cycle may block on a bounded buffer — a fresh one is not "back-pressure", there is no consumer to apply it; (b) staleness is PER SYMBOL, stamped only for a symbol whose quote was stored, never on cycle completion. A service-wide gauge cannot tell 18/18 from 1/18 and prod runs exactly 18 active Quote series whose failures are deterministic per symbol (permanent 403/404, fixed Priority order), so one survivor would hold it at ~60s while 17 sector inputs went stale with neither alert leg firing. CONSEQUENCE, intended: a permanently uncollectable symbol pages until it is DEACTIVATED in finnhub_series — the collector cannot make a delisted or plan-uncovered symbol return data, and TrackActiveSymbols drops a deactivated symbol's series so the remedy takes effect within one cycle; (c) the gauge is read on the OTEL reader's thread, never the collection loop's, so it still reports while that loop is blocked; (d) the durable ORIGIN is finnhub_quote_collection_stamps, whose ONLY writer is the collection loop, read once at startup — process start is the fallback for a symbol that store has never seen, because an origin that resets per process is a corpse-detector with a reset button (a container looping faster than the alert's 6h threshold holds staleness under it forever while collecting nothing). max(collected_at) from finnhub_quotes is NOT a substitute and was the previous, broken source: that table is also written by admin-collect / the `trigger_collection` MCP tool, which is the first diagnostic anyone runs during a stall, so a manual trigger ten days into an outage would move the origin forward and re-blind the alert at the next restart (in-process the admin path correctly does not stamp — the leak only opened ACROSS a restart, so no live smoke test would have shown it). last_collected_at on finnhub_series is equally unusable: admin-collect bumps that too. A seed may only replace the process-start FALLBACK and only with an OLDER instant: it can never overwrite a stamp (so hosted-service start order cannot make a healthy cycle read 16 days stale) and can never move an origin forward (so a skewed DB clock or future-dated row trips the alert instead of silencing it); a rejected seed is logged by name with BOTH the stored value and the origin in force, because a rejection that logs like a success is how an operator watching a boot loop is misled; the FALLBACK itself is read from the OS (Process.StartTime), never captured in a field initializer: `const string Name` is inlined by the compiler so Program.cs's AddMeter(Name) does not run the static constructor, the first real access lands after MigrateWithRetryAsync returns, and a fallback captured there understated staleness by the whole boot duration — unbounded, since no lock_timeout is set on that connection — in the direction that makes the alert LESS likely to fire; (e) the alert carries an absent() leg — a threshold on a vanished series selects nothing and can never fire, and nothing else watches this service (no up{job="finnhub-collector"}; service-health.yml scopes ServiceDown to job=~"otel-collector"); (f) a DETECTION failure is itself a firing condition, and the gauge that reports it must measure the OUTCOME rather than its input. finnhub_quote_staleness_origin_durable is PER SYMBOL and reads 1 only for a symbol whose origin was EARNED — an accepted seed, or a stamp write that reached the store — so `min()` over the tracked set says what the alert claims it says. A service-wide flag set from the stamps table's ROW COUNT does NOT: it asserts 'the table was non-empty', a different proposition, and the two come apart with no clock skew anywhere. The stamps table has NO delete path, so rotating the tracked universe leaves rows only for symbols TrackActiveSymbols then PRUNES; every seed is accepted, every ACTIVE symbol keeps the process-start fallback, and a container looping faster than 6h holds staleness under the threshold — absent() false, max() ~0, disarmed leg 1: all three legs false, indefinitely. Durability is keyed on the WRITE and not on collection, because a cycle whose stamp write keeps failing collects fine and still comes up on process start after the next restart. It self-clears per symbol: the cycle that persists that symbol's stamp arms it, so a fresh deployment reads 0 for the ~90s before its first cycle completes and never for the 15m the alert dwells. CARDINALITY: 2 series per active Quote symbol, 36 in prod today, and bounded only by the current data — see docs/BACKLOG.md; (g) the deactivation remedy in (b) is BOUNDED, and nothing in the first two rules bounds it. Deactivating a symbol removes it from BOTH gauges, so following the printed remedy after a 17-of-18 stall leaves absent() false (one series remains — absent() needs ZERO), max() at ~60s, min(durable) at 1, and FinnhubCollectorQuoteErrorsSustained silent because a deactivated symbol is never collected and can never fail: 17 sectors permanently dead and permanently silent, reached by obeying the alert. FinnhubCollectorQuoteSymbolCoverageDropped watches the SIZE of the published universe against a hardcoded 18 for that, and the hardcoding is the point — adding or retiring a symbol is a deliberate two-file act. A self-referential form (`count(...) < count(... offset 7d)`) needs no constant and goes blind to a one-a-week drip, which is the case that matters.
