PURPOSE: identity+classification(NAICS/ATLAS-sector)+source-routing. Not price/obs (atlas_data=cross-DB read-only).

DATA MODEL + INVARIANTS:
  Instrument 1-N SourceMapping · 1-N Alias · 1-1 Embedding(bge-m3,unique(InstrumentId,Model)); ->FK AtlasSector(11)
  SignalIdentity = macro handle (FOMC/CPI), not an Instrument; sector=null always.
  AtlasSectorCode/RollupVersionId = plain cols, not DB-FK (real FK->atlas_sectors on naics_sector_rollup).
  INV identity⊥coll: 0 SourceMappings->ResolveAsync=SourceResolution{Warning} not NotFound. "CatalogInstrumentMissingSector" fires whenever AtlasSectorCode=null.
  INV sector-gate⊥asset-class: AtlasSectorCode req only Equity; Indicator/Economic/Rate/Commodity/Currency/Crypto=null-sector valid. Never gate non-Equity (~87% catalog dropped).
  INV asset-class-canonical: asset_class stored as ONE canonical spelling, normalized at the persist boundary (D-5: case-fold + clear-synonym merge fx->Currency/Interest Rates->Rate/treasury->Rate); consumers compare by exact value. Distinct/ambiguous long-tail (Economic Indicator/Credit/Monetary/fred_series) stays PASSTHROUGH — never auto-merge (Economic Indicator is a consumer sentinel). In-app Equity sector gate (InstrumentMeetsSectorGate) is already OrdinalIgnoreCase — the divergence bit value-exact consumers (ops gap query, SearchAsync filter, AV-promote), not that gate.
  INV exchange-canonical: exchange stored as ONE venue code per listing venue, normalized at the same persist boundary (D-19: CLEAR spellings and a decorated exchCode resolve to ListingVenueRegistry's code; a blank or a pipe-separated paste becomes NULL). Ambiguous or unsettled spellings (FRED, GRETAI SECURITIES MARKET, KARACHI ..., COMEX) stay PASSTHROUGH — adding one is a reviewer-approved vocabulary decision, as an AssetClassNormalizer synonym is. A VENUE CODE IS NOT AN ISO COUNTRY CODE (AT=Australia, SS=Stockholm, NL=Nigeria, PL=Lisbon, GR=Germany): read ListingVenueRegistry.CountryOf, and never compare exchange to country — measured 2026-09-21, no code does.
  INV symbol-unique-among-ACTIVE-only: idx_instruments_symbol is PARTIAL (WHERE is_active) since migration
    ScopeSymbolUniquenessToActiveRows. A symbol names at most one LIVE instrument; any number of QUARANTINED rows may
    share it. A soft-deleted row no longer reserves its ticker (the 2026-07-18 quarantines retired 82 real tickers
    that way). Consequence: a 23505 on that index now means an ACTIVE collision ONLY, and every symbol lookup must be
    single-valued by construction -- all of them filter IsActive except GetBySymbolIncludingInactiveAsync, which
    orders active-first (D-11). ✗ never assume a symbol selects one row without an IsActive filter or that ordering.
  INV lazy-load: self-seeds from SEEN; never bulk-preload.
  INV is_primary: FredCollector is_primary=SOLE trust signal, not asset_class str. empty FRED=ANOMALOUS.
  INV Embed 1-N: unique(InstrumentId,Model), not 1-1. entity-default="nomic-embed-text" DRIFTS; runtime=bge-m3. never infer active model from entity-default.
  INV retired⊥active: retired_at (D-13) is ORTHOGONAL to is_active. A retired row is still a real identity — every
    exact symbol/alias lookup and gRPC ResolveBatch keep resolving it (D-11 untouched) — it only leaves the
    PROPOSING tiers (fuzzy SearchAsync, vector, upstream discovery) and the HNSW index, through ONE predicate applied BEFORE the LIMIT:
    InstrumentSearchScope.Proposable = is_active AND retired_at IS NULL. Written by the D-13 migration and by the
    persist stamp on a "(DISCONTINUED)" name; NEVER cleared at runtime (FRED reactivation included).
